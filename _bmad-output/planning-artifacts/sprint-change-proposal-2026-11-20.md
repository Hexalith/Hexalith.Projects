# Apply the Projects technical audit to the sprint plan

## 1. What triggered the change

The 20 November audit found that important production guarantees are already specified, but several tests prove them using a different host, a smaller failure window, or a different CI job than the one the user relies on. Jerome requested that the recommendations be applied through Correct Course. This record assigns the work and defines how to accept it. The audit provides the full file references, commands and results. [Technical audit](https://chatgpt.com/space/page_b74b02eb60048191adf38fdb0196de7f)

Three outcomes take priority. The shipped hosts must enforce the same authority as the verified topology. A Project must acquire its Folder before activation, and a confirmed write must survive retries on another replica. A full release must carry evidence from an authenticated user journey on its own source revision. Tenant journal recovery also needs an executable procedure while the legacy reads serve as a rollback path.

Reducing MVP scope would require changing explicit authorization, durability and release requirements. The audit supplies a reason to measure both read paths before funding a storage redesign.

## 5. Implementation handoff

The Product Owner and Projects Developer own sequencing for this **moderate** correction. Start with the release fixture and the deployed worker topology because their answers establish which user journey can run and which host boundary is exposed. The test owner records revision, host role, command, expected state and observed state for each accepted case.

- **Projects and Test Architect** own the local host registrations, readiness probes, disposable install check, interrupted-workflow fixtures, journal rehearsal and performance baseline. For the Server migration, coordinate the existing DW-63 work with the EventStore owner. The ordinary worker registration can be addressed independently.
- **Platform Identity and Deployment** supply effective workload identity and ingress evidence. **EventStore/platform, Folders and other participating owners** supply pinned task and receipt contracts. The Product Owner can use the proposed implementation estimates once those contracts are accepted.
- **CiCd, Builds and Release Engineering** own the credential binding, full-release policy and immutable workflow pins in their respective repositories. Capture the redacted run/job result for the candidate. Jerome and John retain the terminal release decision.
- **Sprint tracking** carries the proposal pointer and additional evidence requirements on 7.1-P2, 8.8-P1 and 8.11-P1. The implementation handoff is recorded here. Story 6.7 is in review, 7.1 is blocked and Epics 7 and 8 are in backlog. [Sprint tracker](../implementation-artifacts/sprint-status.yaml)

The sprint-planning review covers the trigger, current and future epics, PRD, architecture, UX, options, story edits and owner handoff.
