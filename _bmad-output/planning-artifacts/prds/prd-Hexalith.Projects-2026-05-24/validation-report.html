This PRD holds up as a chain-top product contract: §2.1 names real trade-offs, §2.4 makes omissions explicit, and most FRs carry testable consequences under a shared §5 recovery contract. What is at risk is silent product invention — UX, architecture, and stories must still decide what makes a match exclusive enough to skip confirmation, which evidence is required for Complete versus Partial, and how to treat brownfield folderless Projects that the addendum admits and the PRD's present-tense invariant denies. status: final is earned for direction; it is not earned as a claim that no product questions remain for downstream work.

The isolation review materially shifts the gate: the confirmation boundary and Conversation membership can be satisfied on paper while still silently attaching work or moving membership without a move. Planning-drift does not remumber FRs, but the folder is stale as a current baseline — §2.5 still reads phase-unblocked while addendum E-17 is NOT READY and later approved SCPs were never reconciled here.

Decision-readiness

strong

A decision-maker can act on this document. §2.1 states choices as choices and names what was given up: one Conversation per Project, one Folder as authorization anchor, current recomputation over persisted inference history. §2.3 is blunt: a core-only build is internal evidence, not an authorized production release.

The remaining weakness is over-clearance, not missing trade-offs. §2.5 asserts that no phase-blocking product questions remain while several product rules those workflows must source are still implicit.

Substance over theater

strong

The furniture test mostly fails to find furniture. Five named journeys earn distinct confirmation, recovery, isolation, and restore behavior. NFRs are product-specific envelopes, not “must be scalable / secure / reliable.” The one theatrical patch is success metrics that restate NFRs.

strong

Adversarial isolation / authority

review-adversarial-isolation.md

This PRD talks like a fail-closed isolation contract and then leaves the enforcement hinges as client honor system. Tenant-scoped metadata-only language is real; it is not a substitute for same-Tenant reference invariants, an exclusive Folder anchor, or a field allow-list that keeps Setup and titles out of operator/export channels.

critical

Actor-selected vs inferred is not a server fact; SingleCandidate can durable-attach without FR-14

§1, FR-6, FR-9, FR-10, FR-12, FR-14, SM-C1
Nothing defines how the server distinguishes actor-selected from inferred. A Chatbot or delegated caller that receives SingleCandidate can call link as actor-selected and skip confirmation.
Fix: Treat any association whose Project id originated in Resolution, proposal, or attachment match as inferred. Require FR-14-class confirmation including for SingleCandidate.
critical

Conversation unlink plus actor-selected link bypasses FR-7

FR-6, FR-7, FR-11, §2.1, §4
FR-11 allows a legal zero-Project Conversation. The next actor-selected FR-6 link then skips FR-7’s dual-Project Preview and audit.
Fix: Forbid Conversation unlink, or classify any link to a previously membered Conversation as a move with the same dual-target Confirmation Artifact.
high

Same-Tenant is not an invariant on links, moves, or resolution inputs

NFR-1, FR-6, FR-7, FR-9, FR-10, FR-13
Authorization on both ends can still link Tenant A’s Conversation or Folder into Tenant B’s Project.
Fix: Add a fail-closed same-Tenant predicate on every reference. Authorization on both ends is necessary and not sufficient.
high

Permitted Projects has no grant, share, or deny model

§3.2, FR-2, FR-5, FR-16, NFR-1, SM-3
No FR creates, lists, or revokes actor permission. Implementers will default to Tenant-wide Project User access.
Fix: Specify the v1 actor-authorization model and grant/revoke operations, or declare Tenant-wide access and drop the actor-leakage claim.
high

Same-name Folder creation can attach a foreign workspace

FR-1, FR-19, FR-23, addendum §5
Neither create nor restore says create-only, nor forbids binding an already-existing same-name Folder or another Project’s anchor.
Fix: Same-name means a create that fails closed on name collision. Binding an existing Folder requires an actor-selected Folder id plus confirmation.
high

The Folder is a cardinality rule, not an exclusive authorization anchor

§2.1, FR-8, FR-16, UJ-4
Nothing says a Folder is bound to at most one Active Project. Two Active Projects can share the same Folders ACL.
Fix: Require exclusive Folder binding for Active Projects, or declare shared-Folder as an explicit multi-Project workspace.
high

Delegated callers can confirm if they hold actor credentials plus the artifact

§2.1, §3.2, FR-14, addendum §1.1
A workflow that requests Preview as the actor can consume the artifact in the same hop — autonomous confirmation with extra ceremony.
Fix: Bind every action decision to the original actor. Do not return a consumable confirmation token to Service/Workflow Callers.
high

Tenant Project Administrator reconciliation is an unbound authority expansion

FR-22, FR-1, FR-7, FR-14, FR-15, FR-23
No FR lists what reconciliation may change. An Administrator can finish membership without the original Confirmation Artifact bindings.
Fix: Reconciliation may only retry or compensate an already-admitted task against its original bound targets. New intent requires a new Preview.
high

Metadata-only still ships Setup, names, and titles through operator channels

FR-3, FR-17, FR-21, FR-22, FR-24, §2.4, NFR-1
FR-24 has size/row caps but no field allow-list. Operators get prompt-adjacent Setup and human-readable titles.
Fix: Publish an allow-list of identifiers, lifecycle, versions, and safe codes. Exclude Setup bodies, names, titles, and paths unless a separate content-inspection permission exists.
medium

FR-6 does not inherit FR-7’s dual-membership fail-closed

FR-6, FR-7, NFR-4
Two concurrent actor-selected links, or a link racing a move, can leave two memberships or a Conversations/Projects split brain.
Fix: State the same atomic invariant on every membership mutation.
medium

FR-3 silently changes the context-assembly policy

FR-3, FR-16, §2.1
Setup updates source inclusion/exclusion with no Preview, so a silent write can admit previously excluded references.
Fix: Classify inclusion/exclusion policy as confirmation-required, or snapshot it into Conversation-start confirmation.
medium

Relink is in the role matrix and audit list but is not an operation

§3.2, FR-7, FR-8, FR-11, FR-21
Implementers will invent a silent relink as unlink+link, granting Administrators a confirmation-free retarget.
Fix: Strike “relink” or define it as FR-7/FR-8-class Preview for every reference kind.
medium

FR-24 permission is not a disclosure control

§2.3, FR-5, FR-22, FR-24, NFR-5, NFR-6
FR-22 is pageable with no iteration cap. FR-24’s caps bound a package format, not access. A CLI/MCP Operator can reconstruct the same metadata without FR-24.
Fix: Cap or purpose-limit FR-22, or retract the “alternatives to unbounded troubleshooting” claim.
medium

Pre-activation safe status can leak reserved workspace intent

FR-1, FR-2, FR-5, FR-22
“Safe” is undefined. A status payload that includes proposed name, reserved Project id, or initiating Conversation id is a diagnostic channel around folder-gated activation.
Fix: Define the pre-activation allow-list: task id, Task Status, safe reason/recovery codes, expiry.
medium

Denied vs NoMatch can distinguish a foreign Conversation

§5, FR-12, NFR-1
An actor who guesses a Conversation id learns whether the resource exists and is unauthorized versus exists and has no Project.
Fix: Collapse Denied, NoMatch, and nonexistence for unauthorized or cross-Tenant Conversation inputs.
medium

File/Memory links escape the Folder authorization anchor

FR-8, FR-9, FR-10, FR-16
A Project User can assemble context from files and Memories that never sat in the Project Folder, including resources authorized in another Project’s Folder.
Fix: Require File References to be descendants of the bound Project Folder, or require confirmation that names the foreign Folder/Project.
low

FR-19 rejects secrets has no detection rule

FR-3, FR-19, NFR-1
There is no definition of a secret, so users will paste tokens into user-facing instructions.
Fix: Define rejectable classes and treat residual Setup as sensitive.

Idempotency scope can cross Projects for the same actor

glossary, NFR-4, FR-1
An Idempotency Key is scoped to Tenant, actor, and operation, not Project or target. Reuse on a different Project returns another Project’s task.
Fix: Include action targets in the idempotency scope, or treat target mismatch as a conflict.
