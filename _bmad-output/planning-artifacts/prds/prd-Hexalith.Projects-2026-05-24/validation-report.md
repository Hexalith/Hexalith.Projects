**[Adversarial isolation]** — Confirmation Artifacts retain the self-confirm weakness FR-25 was written to remove from Selection Evidence (§2.1, §4 Confirmation Artifact, FR-14, FR-15, FR-6, FR-7, FR-11, A-6, addendum §1, §2, §6)
The revision's justification for FR-25 is that Selection Evidence "is minted by the actor's pick, never by an API call a caller makes on the actor's behalf" and, in the addendum, "there is no mint API a caller can invoke on the actor's behalf. A client-asserted flag is not acceptable." That is a statement that a server-issued, session-bound, single-use token returned to Chatbot and sent back by Chatbot proves nothing about a human, because Chatbot holds the session on both legs. A Confirmation Artifact is precisely that token: Preview returns it to the "dual-principal adapter (Chatbot, Web, CLI) that carries that session", confirm consumes it, and the only thing standing between a Chatbot bug and a bound Inferred Association is the sentence "cannot originate or self-confirm", an obligation Projects cannot observe. Attack: Chatbot receives `SingleCandidate X` (no `ConversationLinked`), calls Preview for FR-6/FR-14 on the user's session, receives the artifact, and calls confirm without rendering the comparison FR-14 requires. Every FR-14 consequence is satisfied from Projects' side; SM-C1 ("the share of Inferred Associations bound without FR-14 confirmation is zero") is unmeasurable because Projects records a confirmation. The same path self-confirms archive (FR-4), unlink (FR-11), move (FR-7), and proposal creation (FR-15). A-6's fallback ("until the FR-25 component exists on a surface, every additive link ... is an Inferred Association requiring confirmation") therefore routes the case FR-25 hardened onto the weaker gate.
Fix: Apply the FR-25 mechanism to confirmation: state in §4 Confirmation Artifact and FR-14 that on Chatbot the accept/decline and confirm/cancel controls are rendered by the same Projects-owned interactive component, that the artifact is consumed only by that component's submission on the actor's session, and that Chatbot's adapter transports Preview bodies but never the artifact itself. Until that component exists, make Chatbot's non-self-confirmation a named NFR-11 release-evidence item in addendum §6 (an authenticated test that the confirm path is unreachable without a UI event) rather than an unverifiable obligation.
