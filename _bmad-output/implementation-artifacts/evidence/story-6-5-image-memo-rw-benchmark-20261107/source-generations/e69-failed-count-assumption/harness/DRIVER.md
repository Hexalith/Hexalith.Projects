This directory is a file-only standalone benchmark preparation. No restore, build,
assembly load or measurement has run. Root and the independent reader must review
the complete source/input freeze before any command in commands.json is released.

The executable has the ordinary SDK's existing friend assembly name but is built
only under this temporary directory. Its only ordinary raw references are SDK5bb
and Contracts, with the installed ASP.NET framework reference. It does not build
application projects, load the real Server.Tests assembly or construct a host.
The actual SDK and copied control/candidate are in one unoptimized Debug process.
The two copied variants have their own exact selected scope/fresh/technical path.

ImageInventory reproduces the existing owner+DomainService+owner direct-reference
cohort and original Ordinal FullName order, requiring the expected actual67 count.
This is the source-derived owner/Domain/direct-reference cohort, not a proof of the
complete Domain ExecutableOwners union: discovery projection/aggregate/processor/
query-handler owners are not constructed or asserted to be a subset of these67.
The resolver loads that ordinary owner's dependency graph for Assembly keys and
loaded MVID metadata. It never invokes DevelopmentDomainRouteCatalog or any other
DomainService method. The oracle computation uses the pinned compiled SDK5bb via
the typed friend adapter; each copied computation uses its own typed adapter.
An image Assembly key can be in the inventory resolver's context while the oracle
SDK code is in Default; this is metadata/read input, not a cross-context scope call.
Actual locations/bytes/full hashes/MVIDs/order are saved by the future run.

The entire67 stays in the workload even if an original image/budget bound prevents
full retention. Per-image eligibility, total charge, actual occupancy and actual
scope hit counts are reported. Exact67 retention/hit assertions are conditional
on the complete cohort fitting the original16MiB/64MiB/128-entry bounds. Otherwise
non-hit outputs are kept as unclassified fresh computations: no assumption that
every non-hit is a cache miss rather than an ineligible/rejected fallback.

A small-fit real SDK image first proves selected Domain/FreshStream/Technical
calls actually update that variant's scope hits and memo occupancy. Parity must
pass, and all3 variants must then match independent complete SHA and MVID identity
expectations for the entire inventory before any benchmark begins.

Six balanced variant permutations cover each variant twice in each position for
each path/reader count. Each sample starts a fresh shared memo, then records memo-
cold, warmup and warm batches. This means cold memo, not a cold process, JIT, pool
or filesystem. A fresh selected observation scope lives inside every worker and
is disposed after all67 images; no scope is created in the parent and flowed to
readers. One memo is shared by1/2/4 dedicated reader threads. The barrier aligns
only batch start; there are no per-image barriers. Every original fresh file read,
EOF behavior, pool selection, exact equality and SHA remains in the selected path.

Domain67 is a full fresh-stream computation cohort. Technical67 separately stresses
the exact original PE/MVID/read method across those images; it does not claim that
a real host makes67 technical identity calls. Neither is whole host configuration,
catalog capture or distributed deadline acceptance. The original observations and
authority checks are not removed.

Raw samples retain each observation wall/allocation count and batch wall/process
CPU/managed allocation/GC counters. Scope creation/disposal, exact-output checks and
fixed measurement bookkeeping are included identically. Discovery, parity, expected
SHA setup and JSON output are outside batch timing. Process metrics include batch
release/join and whole-process activity; they are not per-thread CPU attribution.
Batch wall divided by observations would be amortized wall/throughput, not request
latency. Actual Observation.ElapsedTicks gives the observation latency distribution.
No GC is forced, no CPU override is set at runtime, and ServerGC must match the
actual ordinary Folders runtimeconfig. Both SDK and harness must prove Debug with
JIT optimization disabled. All raw samples remain; summaries make no automatic
candidate benefit or live critical-path claim. Baseline/control timing agreement
must be evaluated before interpreting a candidate difference.
