This scratch tool is a diagnostic preparation, not Story6.5 acceptance. It changes no repository file, application operation, authority check/order, deadline, runtime environment or expectation. Parent owns the ordinary managed launcher and all topology lifecycle. No profiler is attached until the first actual MULTIPLE readiness observation fails; a genuine first MULTIPLE positive skips profiling and leaves the ordinary browser flow running without a profiler.

The conditional watcher is watch_live.py. It reads complete readiness JSONL rows, ignores a partial final row, and treats end-only run.json as an optional completion check. It independently locates only fresh private apphost-session receipts after the parent release time, matches AppHost/CLI kernel start identities, verifies the exact source AppHost executable/DLL map and its known configuration-path environment key, and hashes the matching private configuration without parsing/logging its contents. It captures describe metadata through that exact owned CLI and configuration/namespace, selects the unique eventstore resource with the exact source project path and a stable wrapper kernel identity, discards the graph, then traverses only that DCP wrapper descendant tree to select the unique actual Hexalith.EventStore entry runtime. DCP resources can be detached from AppHost OS ancestry, so ownership is bound through the AppHost resource graph, matching the managed launcher. A ready receipt must already have been published before a failed MULTIPLE can request attachment. Only after ancestry/source classification does it read XDG_DATA_HOME and EventStore__DomainService__AppId, retaining only boolean identity facts. Runtime resource alias eventstorehost means this actual entry host, not a process named Gateway. Gateway SDK DLL map/path/hash, source entry assembly hash, all41 pinned owner source hashes and the owner receipt are verified. Earlier broken end-report/mapping standby watcher preparations remain separately retained; they never attached.

The profiler identity file is private and temporary. It contains Role=gateway, Resource=eventstorehost, Pid, StartTicks, RequiredCommandToken, ExecutableSha256, and Files[{Label,Path,Sha256}]. Required file labels are gateway-assembly, owner-config and source-audit; watcher also adds eventstore-entry-assembly and all pinned owner source files. The collector rechecks exact process start identity, strict command-line option/value whitelist, all pinned hashes and the mapped Gateway SDK file immediately before attaching. Sensitive/unknown arguments or uncertain identity skip attachment with fixed reasons. No actual argv, configuration contents, environment values or whole maps are printed or retained.

Exact provider settings are Microsoft-Windows-DotNETRuntime, keyword0x1, levelVerbose5, requestStackwalk=true, requestRundown=true,64MiB runtime buffer. .NET10 manifest event10 GCAllocationTick versions0–4 uses GCKeyword0x1/Verbose. Version4 supplies TypeName,AllocationAmount64 and ObjectSize. No GCHeapDump,ManagedHeapCollect,logging,HTTP,network,CPU-sampling or payload providers are requested. No forced GC is invoked. Cached DiagnosticsClient0.2.510501 explicitly documents the NET9+ stackwalk option and end rundown for dynamic stack decoding. TraceEvent3.1.21 provides EventPipe→ETLX conversion and CallStack/FullMethodName; symbol/source/PDB lookup is disabled. Proof sources and canonical primary revisions are retained locally. The manifest is the .NET10 base contract; actual captured event-version/loss/stack coverage must still be checked on the installed patch runtime.

One returned diagnostic session is collected for up to8seconds across the next2–3 actual failed MULTIPLE windows. Data drains continuously. The finite raw file cap is256MiB, with graceful Stop requested at224MiB to reserve32MiB for rundown;64MiB is only the runtime buffer and is not claimed as a file cap. Hard file cap, target stream end, collection CPU/RSS guards, stop/drain timeout or parser cap/loss yield explicit incomplete flags. Only the returned EventPipe session is stopped. Collection checks CPU4seconds/RSS512MiB at100ms intervals; these are observed stop guards, not OS hard memory quotas. External supervisor bounds collection child to55seconds,CPU hard41seconds and observed RSS768MiB, parser to60seconds,CPU hard46seconds and observed RSS1GiB. An emergency guard signals only its directly owned diagnostic child, never the Gateway, AppHost, sidecars or managed launcher. No topology cleanup or cutoff is performed by the watcher/profiler.

Raw nettrace and derived ETLX can contain CLR event187 RuntimeInformationStart CommandLine/RuntimeDllPath even with the GC keyword. Therefore they exist only in a fresh0700 owned directory with0600 files, never enter a public evidence packet and are hashed/deleted after parsing. The supervisor finally removes every non-allowlisted derivative (including partial ETLX/.tmp files and empty directories), never follows/hashes symlink targets, and verifies absence. Only known sanitized JSON receipts, allocation-samples.jsonl and allocation-summary.json may remain. The source/code/cleanup proof captures this limitation explicitly. cleanup-guard-smoke.json records a successful no-target test covering nested partial derivatives and file/directory symlinks; the external marker remained unchanged.

Offline output is sampled allocation-byte estimates by managed type and physical allocation stack, source event-name counts, missing type/stack and unresolved frame counts, truncation/cap counts, lost-event counts and bounded UTC/relative sample metadata. It emits no object addresses, IPs, module/source paths or unrelated event payloads. FullMethodName is used only through a strict identifier whitelist; empty, address/path/native fallback or oversized formats become [unresolved]. GCAllocationTick weighting is sampled and cannot be interpreted as exact per-type allocation accounting. Physical stacks do not reconstruct logical async parents. UTC samples can be aligned to observed readiness windows, whose fixture elapsed includes later evidence reads. Profiling overhead is not ordinary latency proof.

The final tool build is Debug, cached/offline restore only; exact argv/environment override whitelist, logs, hashes and exit0 are in compile-debug-receipt.json. No module/application Release binary was built. Earlier scratch Release build and two failed preparation attempts remain history. Only Program.cs is a compile input; downloaded primary source .cs files are proof data, not compiled into the tool.
