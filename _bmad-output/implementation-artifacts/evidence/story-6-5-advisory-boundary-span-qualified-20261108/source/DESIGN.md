# Attachment advisory boundary-span proposal

This is file preparation only. No compile, application assembly load, process inspection, sink-directory access, counter window, test, build or host is performed or released. The accepted terminal qualification remains separate: 49 cases × four modes, three first-business flow canaries and four state-protocol cases, with zero new native cases or live approval.

Only a new `AdvisoryTerminalCapture` copy changes. Helper `112af486`, bootstrap `8f5836d1`, private executor `d36afcb5`, differential executor, all original business statements/markers/catches/CTS/awaits/callbacks and the existing terminal fields stay unchanged. The old adapter `9a210774` is preserved byte-exact. `source-proof.json` contains the reversible adapter edits and exact copied-input hashes. No new ambient state, context, token, exception, DTO, string, callback, identity or request read crosses the recorder boundary.

The adapter's existing `Enter` method first stops its active interval at every valid marker, then updates the existing last-boundary field and starts an interval only for a selected marker. InitialScope, InitialInputs, Index, Discovery, FinalInputs and FinalCandidates map to the six unused helper stages. EnvelopeValidation, FinalScope, InitialConversation, FinalConversation and Response end a prior interval but start none. The accepted executor already disables this recorder for conversation calls; retaining those enum cases prevents accidental gap widening if the adapter is exercised directly.

An existing `Failure` notification stops the interval before retaining the original first-failure terminal observation. `Close` stops it before encoding the unchanged six terminal values in stage 4. `Dispose` invokes `Close` as before, so release is idempotent. Each selected marker occurs at most once on an ordinary attachment invocation. An unexpected selected-marker repetition disables further span recording without changing terminal behavior, preserving the first interval instead of overwriting its helper slot. Allocation mode is always None. A failed/null interval also disables later spans; diagnostic failure never changes business control flow.

Helper 112 stores only one interval per stage and emits counts only on stage 4. Therefore this proposal does not use repeated ComponentFile rows or move boundary IDs into other count slots. There are at most six boundary rows, the existing Whole row and terminal stage-4 row: eight rows per admitted capture, below the proposed upper bound of twelve. Missing/zero-duration/dropped rows are unobserved, not a zero interval or proof a marker was skipped. Capped or failing sinks may retain only parts of a capture.

A span measures recorder timestamps from an existing marker notification to the next valid marker notification, first catch notification, or close. It includes intervening original work and diagnostic bookkeeping, scheduling and any waiting. It does not identify an await duration, lambda entry, candidate count, remote activity, caller cause or deadline cause. Marker 6 still precedes candidate-array creation and Parallel scheduling. An expired linked token can therefore end this span before any final-candidate callback starts.

The omitted gaps remain unattributed: admission-to-InitialScope, EnvelopeValidation-to-InitialInputs, FinalScope-to-Response, Response-to-close, and any unselected marker interval. Whole includes the unchanged capture admission bookkeeping after its timestamp, the method body and unwind until helper disposal. Six selected spans are disjoint when retained, but their difference from Whole is not an exact measure of any one omitted activity. No joins to the previous terminal run, old receiver/transport captures, requests, identities or expiry are made.

The Tenant store inspection did not justify a production repair: the read performs one strong typed Dapr read, then a manual detached copy of four collections and scalar fields. There is no repository-side read-path JSON reserialization. Projection size and clone cost are not measured by the current terminal result. This boundary split is a diagnostic proposal, not an optimization or causal conclusion.

Concrete qualification apparatus is now staged under `differential/`. The same 49 cases and original business/exception/token/dependency comparisons are retained in four modes. Closed numeric helper durations are read only after disposal, compared against independent original-branch stage masks, checked immutable after held children join, and matched exactly to persisted rows in zero-drop groups. The unchanged three fresh-flow canary sources still perform their first business call before helper reflection. Ten new adapter cases run after the four retained protocol cases in the same fresh protocol process: 14 protocol cases total, still 23 controlled processes. Synthetic waits have two-second per-wait bounds and the late-event join has a three-second bound. `commands.json` lists the future standalone cached restore, Debug build, facts and controller commands; all release flags are false. Current source65 and app147/reference hashes are frozen separately from historical qualified733 input generations. No current mutable spec pin is needed for this code-only scratch proposal.
