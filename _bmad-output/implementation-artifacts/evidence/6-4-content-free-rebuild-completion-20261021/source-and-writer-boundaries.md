# Content-free rebuild completion: source boundary

The existing SDK terminal receipt was not a safe query seam: a caller must fetch its marker row before discovering that the row is prepared/committed and still contains operation paths or rich recovery manifest bytes. Existing `GetAsync` also resolves pending envelopes by reading that marker. No existing API supplied the required physical, marker-free read.

The new original-selection discriminator is `ReadModelRebuildCompletion.ReceiptProjectionName` (`rebuild-completion-v1`). Conversation places it into newly prepared native-backed selection operations before manifest fingerprinting. Existing literal `rebuild` selections remain supported by ordinary SDK paths but are refused by the strict Conversation adapter. They receive no completion record on retry. The discriminator does not certify a native source; existing original admission, metadata digest, scope/catalog, selected generation and current authority gates still apply.

For an enrolled coordinated batch containing that discriminator, the SDK writes `hxrmb:v1:completion:<original-scope-hash>` only after terminal receipt compaction, original manifest reclamation and physical operation read-back. The dedicated bounded record contains only protocol version, original scope/batch/fingerprint/time, exact owners and a canonical integrity digest. It cannot represent manifests, operations, recovery anchors or messages. A competing or corrupt completion is never overwritten. A publication interruption retries the identical original record and terminal time through the existing write/rebuild paths. A mis-qualified partial transaction cannot publish it. Ordinary constructors, JSON, manifest hashing and envelope versions remain unchanged.

The supported owner-proof reader maps the new discriminator solely to the completion namespace, never to the actual rebuild marker. Missing or malformed evidence refuses with no fallback. An older SDK instead hashes `rebuild-completion-v1` as a different marker scope and its old receipt validator refuses the discriminator; it cannot retrieve the actual `rebuild` marker. This is an immutable wire discriminator, not an optional flag that an old SDK could ignore and then fetch rich input.

`IReadModelStore.GetCompactedAsync` explicitly reads a physical value and rejects any SDK envelope before marker access. Dapr and the SDK in-memory store implement it over their actual raw accessors. Its default interface implementation throws unsupported, so old/custom stores cannot silently fall back to resolving reads. The strict Conversation metadata/proof/ledger and native selection reads use this capability. This also closes historical v1 prepared envelopes with virgin or prior proven values. The outer proof still runs first and last; native proof, ETag/generation/ledger coherence, current source/catalog and direct-writer invalidation remain mandatory.

Source-guard canonical tail, qualification and cleanup recognize exactly either the existing `rebuild` discriminator or the new versioned completion discriminator. The production guard/dispatch/persisted-store harness exercises canonical replay, interrupted retry, current native inspection without events/rich marker reads and same-checkpoint qualification in both modes. Conversation integration uses real enrolled SDK staging/commit/owner endpoints and signed delegated client requests; its fixture current transport derives owner evidence from the live SDK endpoint on each invocation. It is not a deployment or installation authority.
