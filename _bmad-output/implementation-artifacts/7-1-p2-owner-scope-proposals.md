# 7.1-P2 owner scope proposals

Projects needs two owner capabilities before it can qualify folder-first activation. Story 8.1 also needs the committed task status and receipt contract for reconciliation acceptance. These proposals request repository-local scope approval and qualification in isolated persisted fixtures. The owner revisions below identify the inspected source. The accepted P2 pin will require the exact delivered revisions and decisions. [Projects package definition](../planning-artifacts/epics.md#story-71-prerequisite-work-packages) · [Evidence and approval requirements](../planning-artifacts/sprint-change-proposal-2026-11-24-readiness-blockers.md#51-first-writer-and-epic-6-evidence)

## G-1 Durable Task admission and recovery

**Decision requested from the EventStore Owner.** Approve an owner-local design and implementation scope for generic Durable Task admission, atomic Confirmation Artifact consumption where applicable, committed task status and receipt lookup, and fenced execution and recovery. EventStore revision `ae1143bdc831ca6f2cf61726648a3efe946d68a2` has conditional checkpoints, leases and effect receipts in `CheckpointedProcessRunner` and `ProcessCheckpointStore`. Evaluate those primitives for reuse against task admission, original-actor binding and the confirmation transaction. Projects supplies its workflow semantics and consumes the resulting owner contract. [EventStore checkpointed processes](../../references/Hexalith.EventStore/docs/guides/checkpointed-processes.md)

**Decision requested from the Platform Owner.** Decide the supported package and runtime, persistence provider, lease semantics, scheduler and two-replica qualification topology. Platform revision `f7635b592b0499a1c0888b91d1e3be4b0a2d7f78` places this engine outside its MVP. Record how the EventStore candidate will be qualified and rolled back within an explicitly approved Platform scope. Pin the runtime inputs and operating limits that the fixture actually exercises. [Platform scope](../../references/Hexalith.Platform/_bmad-output/specs/spec-platform/SPEC.md) · [Projects architecture decisions](../planning-artifacts/architecture/architecture-projects-2026-07-15/ARCHITECTURE-SPINE.md)

**Qualification.** Run both task-only admission and confirmation-required admission. In the latter case, prove atomic consumption and task creation by interrupting admission around the commit, then retrying on another replica. An equivalent retry under the same Tenant, actor, operation and key reauthorizes and recovers the original task before spent-evidence validation. Changed intent, invalid evidence on a new admission, or denied authority yields no extra task or effect. Inspect committed task and consumption records.

After a worker crash, expire its lease and resume on the competing replica with the same task ID, original intent and actor bindings, checkpoint and owner receipt. Assert that the stale worker cannot advance and the owner effect occurs once. Inject a lost response and a dependency outage separately. Verify authoritative receipt lookup before retry, a truthful waiting or attention state, and immutable terminal results. Also exercise cancellation before and after the irreversible checkpoint.

**Rollback rehearsal.** Stop new fixture admissions and fence the candidate workers. Run the owner-approved rollback target on the same retained store and inspect existing task IDs, checkpoints and receipts. If the previous runtime cannot safely interpret or resume the retained records, keep mutations fenced and exercise the approved forward recovery. Recheck the original task and effect counts. Capture executable setup, run, fault injection, rollback, verification and teardown commands at the proposed revision.

## G-2 Folder provisioning and owner receipt

**Decision requested from the Folders Owner.** Approve an owner-local scope for create-only provisioning, current scoped read/manage authorization, durable provision receipt and status lookup, and an explicit compensation disposition. At `d56e868fd38c1c84f447180b8bfbe525235220f7`, the generic `CreateFolder` path returns task acceptance and has idempotency support. It has no expected-version or sole-manager creation mode. The permission path combines Organization baseline evidence with Folder overrides. `FolderOwnerReadQueryHandler` supplies delegated metadata-read evidence, and the workspace task projection covers workspace operations. Use these paths to identify reusable seams and preserve their existing consumers. [CreateFolder contract](../../references/Hexalith.Folders/src/Hexalith.Folders.Contracts/Commands/CreateFolder.cs) · [Delegated owner read](../../references/Hexalith.Folders/src/Hexalith.Folders.Server/Queries/FolderOwnerReadQueryHandler.cs)

**Contract.** Define the expected owner version or create precondition, the owner identifier shape, and the scope of the deterministic task-step key. Bind the receipt to the committed Folder identity and owner revision, original Tenant and actor, and the admitted step. Qualify the same-Tenant, no-supplied-Folder case for a Project User and an authorized Service/Workflow Caller. The original actor becomes sole manager and the Folder has no Tenant-default read grant. Authenticate the calling workload and use current original-actor authority for the operation. Folder access must never derive from Projects' workload identity. Return a safe collision outcome without selecting or modifying an incumbent Folder.

**Qualification.** Exercise equal retry, changed input under the same key, stale version, same-name collision, cross-Tenant and revoked actor, and owner unavailability. Drop the response after a commit, restart a replica, and use the owner lookup to recover the original receipt before retrying. Assert one Folder history, the intended effective grants, and a receipt that resolves to the same Folder and revision. Check that access loss and dependency outage cannot disclose or bind a Folder.

**Compensation and rollback rehearsal.** A committed Folder with an uncommitted Project goes to `NeedsAttention` with the receipt retained. Any compensation must be an explicitly approved, idempotent Folders operation with current authority and provenance checks. Record where no compensator applies. Exercise the rollback target against the same fixture after provisioning. Verify that it preserves committed history and the incumbent Folder, and that admitted effects remain identifiable for recovery. The existing deployment rollback runbook supplies operational context. [Folders rollback runbook](../../references/Hexalith.Folders/docs/runbooks/rollback.md)

For each capability, return an owner-approved scope and capability record with immutable repository and contract versions, dependency and fixture coordinates, clean-checkout commands, native persisted results with digests, the exercised rollback result, and dated owner decisions. The Solution Architect and Test Architect review and accept the same coordinates. Projects records the pin only after that review.
