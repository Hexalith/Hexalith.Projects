# Supported Project list/open implementation (Story 6.1)

This is local implementation and technical verification, not production acceptance or P4 approval. The unchanged legacy public `/api/v1/projects` routes remain available. The new handlers are `Hexalith.Projects.Queries.ListProjects.v1` and `Hexalith.Projects.Queries.GetProject.v1` at the existing DomainService query dispatcher. List defaults to 50, caps at 200, orders by ordinal Project ID, and accepts `Active`/`Archived` lifecycle filters. The separate conversation page default remains 25.

## Persisted projection and dispatch

`ProjectReadProjectionHandler` reuses the existing pure Project detail fold. The tenant enumeration is the ordered set of successfully created Project IDs. `IReadModelStore`/`IReadModelBatchStore` own persistence, ETags and coordinated visibility; the handler retries optimistic conflicts. Interrupted conditional batches use the SDK pending-key recovery seam described below. Store: `statestore`. Logical keys are `projects:reads:v1:{tenant-length}:{tenant}:index` and `projects:reads:v1:{tenant-length}:{tenant}:{project-length}:{project}`. Per-aggregate Sequence and exact EventStore GlobalPosition are separate; timestamps come from observed events. No synthetic global watermark is used.

The new persisted mutation routes are mapped only when `ProjectAuthorityRuntimeSecurity` is registered and both require the existing workload Project policy; bearer-only hosts expose neither route. The protected `/project/v2` adapter delegates admission, named routing, upcasting and catalog checking to `DomainProjectionDispatcher.DispatchAsync` with configured service identity/options. `/project/rebuild/v1` delegates coordinated full replay to the same SDK. The metadata endpoint advertises the actual handler catalog and platform fingerprint. Legacy `/project` retains its previous stateless response.

The finite relevant catalog is ProjectCreated, ProjectSetupUpdated, ProjectFolderSet, ProjectFolderCreationPending, FileReferenceLinked/Unlinked, MemoryLinked/Unlinked, ProjectArchived/Restored and ProjectResolutionConfirmed. Authority grant/revoke events and the eight explicit rejection types are known no-ops for this projection, but advance exact sequence/position. Unknown types, malformed JSON, identity mismatch, gaps and absent/non-monotonic GlobalPosition degrade the model. A tenant-level unavailable-ID marker also degrades enumeration when the first event for an unknown aggregate fails. The persisted RecoveryFloor records the highest observed failed sequence independently of the last applied Sequence/GlobalPosition. An older prefix cannot clear degradation; valid contiguous redelivery or complete replay must cover the floor. Older degraded records without a floor conservatively require at least the next sequence. Valid complete replay repairs that marker. Retryable persistence failure never advertises success.

## Interrupted conditional batch recovery

The approved local EventStore dependency change adds `IReadModelPendingBatchRecoveryStore.RecoverPendingAsync`. Projects opts its conditional detail/index batch into `ReadModelBatch.RetainManifestForRecovery`, then asks this SDK seam to resolve its own pending keys before reading fresh values and ETags. The platform retains the existing immutable manifest until proven terminal completion or compensation; no attempt registry or additional Projects storage is introduced. The original ETag-dependent BatchId is recovered from existing validated envelope/marker/manifest evidence, not guessed from a pending logical read.

The SDK checks bounded manifest and marker bytes, canonical fingerprint, exact store/tenant/domain/aggregate/projection scope, recoverable marker state, explicit marker status, operation ordinal/key/kind/candidate and previous-value envelope shape/absence consistent with original create-only or match-existing concurrency before resuming the existing protocol. A pending tenant index belonging to a different aggregate is not helped. A proven compensated optimistic conflict permits Projects to recompute a fresh batch with current ETags. After commit, an ordinary row already superseded by a later writer is preserved while remaining own envelopes compact and the original receipt completes; a retry cannot roll the shared index back. This opt-in is rejected before state access when combined with guarded owner selection, preserving the existing guarded-owner recovery semantics.

The earlier failing `InterruptedBatchRetainsBothPriorValuesUntilRetryCompletes` expectation remains unchanged and now passes. Focused SDK cases cover precommit interruption, compensated conflict and a new attempt, interrupted compaction plus another aggregate advancing the shared index, process/store-client recreation, corrupt metadata with zero writes, and mismatched scopes. The same SDK protocol has an opt-in Dapr/Redis failure/restart fixture. Redis remains on its existing Resumable profile; no TransactionQualified selection, operator qualification, production acceptance, package pin or release change is implied.

## Read admission, evidence and audit

Reads bind the immutable tenant, actor, workload, delegation, scopes and configured bearer audience to authenticated authority before protected payload validation. Chatbot requires workload `chatbot`, explicit delegation and ProjectUser; it never falls back to TenantOperator. TenantOperator and TenantProjectAdministrator are the other supported roles. Current Tenant authority is required. Chatbot Project Folder owner-read filtering precedes pagination. Invalid authorized structure/cursors yield safe 400; missing and denied singleton targets share safe 404. Stored descriptive values and raw owner failures never enter denial responses.

Platform `IQueryCursorCodec` protects continuations scoped with `QueryCursorScope` to identity, delegation, audience, action, lifecycle, page size, inspection mode, Tenant and EventStore authority freshness, the SDK index ETag, the current authorization-filtered visibility fingerprint, and exact projection watermark. The entire canonical scope is SHA-256 hashed before SDK protection, keeping the continuation bounded even with long authenticated scope/audience values. The index ETag catches delayed aggregate updates below another aggregate's tenant maximum; GlobalPosition keeps its exact event meaning. Each page reads and authorizes the full lifecycle-filtered tenant set before decoding its continuation, including rows before the prior boundary. Its locally observed per-Project authorization and Folder outcomes form a canonical QueryCursorScope string hashed with SHA-256; this is an observation fingerprint, not an owner revision or permission-version protocol. A new grant before the boundary invalidates continuation. This costs O(N) current authorization/owner reads per page and cannot provide a distributed atomic owner snapshot; an owner revision capability would be needed to avoid the full sweep. Retryable or stale/unavailable authority and Folder evidence return Unavailable enumeration instead of a falsely Complete empty page. The logical continuation has a 15-minute expiry. Authority/projection changes invalidate continuation; callers restart enumeration. There is no Projects cursor cryptography or persistence framework.

AD-32 `asOf` is the injected clock's current computation time. Project/Setup lastVerifiedAt remains the event observation time; Folder/Authorization current verification is separate. Missing/rebuilding/corrupt required evidence is Unavailable. Folderless historical projects are inspectable by authorized Tenant roles but unusable as complete context. Optional File/Memory references retain opaque IDs while their labels are omitted and state is Unavailable (`OwnerReadUnverified`), yielding Partial evidence until current owner authorization can be checked. Project Folder display labels require a successful current Folder owner read. Archived lifecycle stays explicit; a Complete metadata snapshot does not override the lifecycle prohibition on context use.

Tenant-role responses omit Project name, description, Setup and reference display labels by default. Requested descriptive inspection additionally requires the distinct authenticated `projects:inspect_descriptive_metadata` permission. Chatbot descriptions require its Folder-filtered admission. Before inspected metadata leaves the boundary, `ProjectReadAudit` durably writes a metadata-only record through platform `IReadModelStore` and `ReadModelWritePolicy`; audit failure denies disclosure. The request surrogate binds immutable authority, target, payload hash and correlation plus the stable observed revision. Lists reuse the hashed index/cursor scope; open hashes the stable model and Tenant/EventStore/Folder authorization evidence. Unchanged retries reuse one record; the same correlation with a changed observed result creates a new record, including same-count content changes. Fields are outcome, Project count, closed field class, first observation time and hashed request surrogate; no names, actor/Project identities, descriptions, Setup, content or raw denial detail are stored. No TTL is applied (durable retention is at least 365 days). This is a Projects-owned adapter over platform persistence, not a generic platform audit service or formal P4 acceptance. Safe denial also produces only a metadata audit. Reads perform no domain or sibling mutation, resolution or candidate selection.

## Review correction ordering and limits

Opted-in terminal recovery keeps one existing participating envelope as an anchor while other operations compact (or compensate). It then writes Completed (or Aborted) with a bounded, payload-free proof in the existing marker: exact original scope/key/ordinal, candidate and previous byte digests, operation kind and retention. It reclaims the original external manifest, then compacts/restores the final own envelope. Inline manifest payload is removed atomically with the terminal marker. A crash before receipt remains discoverable through the original envelope/manifest; a crash after receipt or manifest reclamation uses the strictly validated terminal anchor proof. After the final envelope disappears, retained payload has already been reclaimed. Later ordinary values are preserved, and foreign envelopes are never helped. No extra key, lookup, attempt registry or scan is introduced. Non-opted and guarded-owner modes retain their ordering and semantics.

Recovery structurally recognizes only a top-level batch discriminator; ordinary string values or nested metadata named `$hxrmb` remain normal data. Before mutation it validates every installed participating envelope against the original manifest, including non-discovery candidates, deletion flags, ordinals and previous bytes. Missing/duplicate envelope/proof fields, unknown statuses and scope/digest mismatches fail closed. Owner response success similarly requires an explicit, unique, defined numeric outcome; missing/malformed owner success and missing signing infrastructure produce Unavailable evidence, never affirmative access or a silently Complete empty list.

The tenant index remains one bounded SDK batch participant. The SDK default canonical-manifest ceiling is 1,048,576 bytes for the complete batch, including encoded detail/index and metadata; the maximum Project count therefore varies with identifier and detail sizes. An oversized batch fails before any state write and leaves both prior values intact. This local scaling limit requires future platform-backed partitioning/qualification for larger tenants; this change does not add partitioning, alter domain command admission, or select a different store profile.

Caller authority captures defensive list copies with ordinal content equality/hash behavior. Oversized gateway claim sets receive a bounded authorization refusal before query dispatch. Request authority is cleared even when handler construction or duplicate-route validation fails. The real production Folders host policy matrix covers query and metadata callbacks as well as process/project.

## Advisory Project suggestions (Story 6.4)

The supported `Hexalith.Projects.Queries.ResolveProjectFromConversation.v1` and `Hexalith.Projects.Queries.ResolveProjectFromAttachments.v1` queries target envelope aggregate `projects` through the existing gateway. The payload is `{ "conversationId": "opaque-id", "includeArchived": false }` or `{ "attachments": [{ "referenceKind": "folder", "referenceId": "opaque-id" }], "includeArchived": false }`.

The retained `GET /api/v1/projects/resolution/from-attachments` route scores only owner-accepted Folder inputs. Its `fileId` query parameter remains for compatibility, but File inputs never score. A legacy File-only request returns HTTP 200 `NoMatch` because File coverage is unsupported; it is not an exhaustive search or evidence that no Project matches. The legacy response has no incomplete/unsupported fields. Consumers that need explicit coverage use the supported attachment query and its `incomplete` and `unsupportedInputKinds` fields.

Responses contain `result`, `candidates` (IDs, ranks, scores, reasons), `evaluatedAt`, `incomplete` and `unsupportedInputKinds`. Empty incomplete evaluation has `result: null`. Names are omitted. Observed metadata may lag; even `ConversationLinked` is only an observed hint. Every suggestion remains unselected and supplies no context or confirmation authority. File inputs currently return `unsupportedInputKinds: ["file"]` and incomplete coverage; Folder/Conversation matching is supported.

Use the same bound-signing configuration described above. Add both Projects query names to `Authentication:QueryAuthority:RequiredQueries:projects`; add `Hexalith.Conversations.Queries.GetConversationAdvisoryMetadata.v1` alongside the Folder owner query in `Authentication:BoundOwnerQuery:AllowedQueries:projects`. Enroll the registered owner query catalogs and retain the real workload/permission policy. Production OIDC bound-authority support remains a separate deployment prerequisite. The Conversation owner uses its ordinary allowed Tenant Read decision, bound to the exact requirement, Tenant and actor; advisory disclosure does not require native permission evidence.

Admission requires `projects.read`, the configured `Authentication:JwtBearer:Audience`, a verified original actor/workload/delegation binding and fresh Tenant authorization with a usable watermark. Operators need `TenantOperator` or `TenantProjectAdministrator`; delegated Chatbot requests need `ProjectUser`. These checks run before owner metadata and again before disclosure.

Payloads are limited to 16 KiB. HTTP 400 rejects malformed JSON, unknown or duplicate top-level fields, unsupported reference kinds, blank/untrimmed identifiers, more than 32 raw attachments, an aggregate other than `projects`, paging and global-admin hints. Missing or denied Conversations return indistinguishable HTTP 404. An existing Conversation found in the tenant summary index whose isolated metadata is not projected yet returns an empty incomplete result. Rich Conversation detail is never loaded for this fallback.

The query selects the ordinal-first 200 distinct Project IDs, with an authorized linked Conversation hint reserving one slot, and reads those Project details, with final rereads of retained candidates, accepts at most 32 raw attachments before deduplication, uses at most four concurrent dependency calls and one linked two-second dependency deadline. The existing index is monolithic; this is a detail fanout bound, not an index-byte bound. Truncation, unusable data and unavailable dependencies yield incomplete coverage. Lag alone does not make usable committed matching metadata incomplete. Folderless Projects (no binding, or Pending with no Folder ID) rely on exact Project Read authorization and its final recheck; attachment matching skips them without incomplete coverage. A bound Folder requires an Included binding and actual owner acceptance. Conversation matching checks Folder owners only for Projects with an observed link or matching scoring label. Empty, File-only, fully denied attachment inputs and Conversation observations without a link or label skip Project fan-out while retaining final authority checks. Queries persist no inference or repair.
