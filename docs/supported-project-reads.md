## Review correction ordering and limits

Opted-in terminal recovery keeps one existing participating envelope as an anchor while other operations compact (or compensate). It then writes Completed (or Aborted) with a bounded, payload-free proof in the existing marker: exact original scope/key/ordinal, candidate and previous byte digests, operation kind and retention. It reclaims the original external manifest, then compacts/restores the final own envelope. Inline manifest payload is removed atomically with the terminal marker. A crash before receipt remains discoverable through the original envelope/manifest; a crash after receipt or manifest reclamation uses the strictly validated terminal anchor proof. After the final envelope disappears, retained payload has already been reclaimed. Later ordinary values are preserved, and foreign envelopes are never helped. No extra key, lookup, attempt registry or scan is introduced. Non-opted and guarded-owner modes retain their ordering and semantics.

Recovery structurally recognizes only a top-level batch discriminator; ordinary string values or nested metadata named `$hxrmb` remain normal data. Before mutation it validates every installed participating envelope against the original manifest, including non-discovery candidates, deletion flags, ordinals and previous bytes. Missing/duplicate envelope/proof fields, unknown statuses and scope/digest mismatches fail closed. Owner response success similarly requires an explicit, unique, defined numeric outcome; missing/malformed owner success and missing signing infrastructure produce Unavailable evidence, never affirmative access or a silently Complete empty list.

The tenant index remains one bounded SDK batch participant. The SDK default canonical-manifest ceiling is 1,048,576 bytes for the complete batch, including encoded detail/index and metadata; the maximum Project count therefore varies with identifier and detail sizes. An oversized batch fails before any state write and leaves both prior values intact. This local scaling limit requires future platform-backed partitioning/qualification for larger tenants; this change does not add partitioning, alter domain command admission, or select a different store profile.

Caller authority captures defensive list copies with ordinal content equality/hash behavior. Oversized gateway claim sets receive a bounded authorization refusal before query dispatch. Request authority is cleared even when handler construction or duplicate-route validation fails. The real production Folders host policy matrix covers query and metadata callbacks as well as process/project.
